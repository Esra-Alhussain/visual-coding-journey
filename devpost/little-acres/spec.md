## Product behavior

Three original settings correspond to the saved garden/bridge/café ideas: meadow farm, broken river crossing, café garden. One shared eight-by-eight isometric world, six numbered crop plots and two crops. Every plot action animates Mochi walking to an adjacent reachable tile. Planting creates a seedling; first watering starts a six-second growth cycle; growth scale updates; golden sparkle marks readiness. Harvest clears the plot and adds one to harvest total/basket. Replanting is supported. Repeated watering does not restart growth; duplicate harvest fails safely.

Meadow requires two harvests and a code-driven change. River requires one harvest, code change and bridge repair; repair needs the first harvest and opens an actual traversal connection plus visiting character. Café requires two harvests, code change and delivery; delivery consumes two basket crops and shows first guest. Continued farming remains available after completion. Switching settings preserves session state and growth timing. Reset affects only current farm; reload clears all.

## Technical boundary

Framework-free local HTML/CSS/SVG/JS. engine.js defines deterministic state, growth, actions, bridge/crop/building collision, BFS pathfinding and safe parser. app.js connects direct tools/code editor to the same controller, sequential timed walking, scene rendering, selection, feedback and optional browser-oscillator sound. No eval, network dependencies or commercial art assets. Original scene consists of layered/depth-sorted isometric tiles, crop symbols, trees, chickens, building/awning/guest, stream/bridge and straw-hat Mochi. Native animation and reduced-motion support.

Accepted code: farm.plant(id, "carrot"|"strawberry"), farm.water(id), farm.harvest(id), farm.repair_bridge(), farm.deliver(), and four move_direction(n) commands. Plot IDs 1–6; steps 1–8; max 24 commands/80 walking steps. Comments/blank lines accepted. General Python/variables/loops are not implemented. Invalid syntax validates before execution. Runtime no-op or collision stops remaining instructions and keeps prior changes. Code earns mission credit only after a successful visible action/movement. Farm commands auto-walk first; explicit movement follows tile axes.

Each cancellation increments execution ID, clears/resolves awaited timers, and re-enables controls. Changing setting/resetting/stopping prevents stale continuations. Date-based crop growth is independent of route timers and keeps advancing after Stop. Only explicit user tool/example actions insert/replace code. Accessible plot/ground buttons, labeled form controls, pressed tool/setting state, keyboard plot activation, tool shortcuts outside text inputs and live status.
