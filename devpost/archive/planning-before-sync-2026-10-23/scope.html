The five-lesson beginner map

Each stop connects an explanation, a small real-code edit and a visible result. Open a stop to see how it prepares learners for the final mission.

  1. 1 Values & variables Make it yours

    Learner edits: Mochi’s name and greeting, then numerical values controlling movement as play actions are introduced.

    Visible result: the name label changes; tapping Mochi speaks the current greeting and displays it in a bubble. Changing distance or height changes the corresponding movement.

    Understand: variables store information; provided display and play code uses it. Editing a value changes the result.

    Final-mission connection: personalize the greeting and set the play values.

  2. 2 Sequence & action calls Give Mochi instructions

    Learner edits: call provided play actions and arrange instructions so Mochi approaches the hoop before jumping. Practice chasing the ball and adjusting its distance too.

    Visible result: Mochi follows the instructions in order; jumping and chasing are practiced before the final mission.

    Understand: named actions do something, and the order of instructions matters. Defining custom functions comes later.

    Final-mission connection: arrange the actions into a working play routine.

  3. 3 Lists Stock the shop

    Learner edits: add or remove supported toys in the products list, including the ball and hoop used in play.

    Visible result: the shop’s displayed stock reflects the list.

    Understand: a list stores several values. Provided drawing code turns supported names into visible toys; the list does not draw pictures by itself.

    Final-mission connection: stock the toys needed for Mochi’s play session.

  4. 4 Choices / conditions Match the toy to the action

    Learner edits: a condition: if the selected toy is a hoop, jump; otherwise, chase the ball.

    Visible result: selecting the hoop and ball produces the corresponding different behavior.

    Understand: code can choose an action based on a situation. This activity uses two supported toys; “otherwise” means the ball, not any unknown item.

    Final-mission connection: test both toys and make each trigger the correct action.

  5. 5 Repetition / loops Play again through code

    Learner edits: repeat a taught play action a chosen number of times.

    Visible result: Mochi performs the action the specified number of times.

    Understand: a loop repeats instructions without copying them again and again.

    Final-mission connection: repeat the appropriate play activity as part of the routine.

Throughout all five lessons: experiment, observe the result, fix mistakes and request hints. Guidance gradually reduces. These are connected skills in one project, rather than isolated exercises.

FINAL MISSION · COMBINE WHAT YOU LEARNED

Prepare Mochi’s play session

Build a working play routine with familiar skills in a fresh situation. Learners receive the goal with fewer instructions and can request hints.

The mission combines

  • A personalized greeting and movement values.
  • A shop stocked with the ball and hoop.
  • Actions arranged in a meaningful order.
  • A choice that matches each toy to its play action.
  • Repetition controlling how many times Mochi plays.

What success would look like

  • The learner’s current greeting is shown and spoken when Mochi is tapped.
  • The required toys appear in the shop.
  • Testing the hoop and ball produces the correct ordered action.
  • Movement values and repetition change the observed routine.

These are proposed observable checks. Exact task targets, validation and unlocking rules still need product-level definition.

Firm teaching rule: every concept and action required by the final mission must first be taught and practiced. The finale introduces no surprise coding concepts.

A celebration and short reflection were proposed as the ending. The short reflection is already part of the agreed journey; exact celebration and reflection interactions remain to be defined.

How learners interact with Mochi

Agreed · tap to hear your greeting

Edit the greeting, then follow a hand cue inviting a tap. Each tap makes Mochi say the current greeting aloud and show the same words in a speech bubble.

Exact hand-cue timing and speech behavior still need definition.

Agreed direction · Try my code

Try my code tests the learner’s edited movement instructions. Taps remain available for Mochi’s programmed interactions, including the spoken greeting. Testing and playing happen on the same screen, without separate modes.

Tapping toys to run code was rejected. Exact execution behavior and instruction highlighting still need definition.

Editor, explanations and friendly errors

Use one growing editor with current lesson lines highlighted and starter code distinguished. Learners write their own edits. When code cannot run, visibly dim the stale preview, highlight the issue and explain a correction; valid code restores the live result. Code that runs with an unexpected outcome should show its actual consequences.

Visual explanations and shop-world stories connect code to the result. In-app AI task/help stories were discussed in the earlier product draft; their exact controls and unavailable-help behavior remain unresolved.
